# 导购内容与商品数据维护指南

> 改内容不用碰架构。绝大多数需求只需改 **2 个文件**：`products.py`（数据）和 `agent.py`（回答逻辑）。

## 〇、先弄清一件事：数据在哪

运行时数据全部在 **SQLite 数据库** `backend/data/smartmart.db` 里。
`app/data/products.py` 是它的**种子数据源**（版本化的初始内容），不是运行时数据源。

所以改数据有两条路，按需选择：

| 场景 | 做法 | 是否需要重启 |
|---|---|---|
| 批量加商品、想留版本记录 | 改 `products.py`，然后 `python -m app.db.seed --force` | 否（灌完立即生效） |
| 临时改个价格、加一条促销 | 用任何 SQLite 工具（DBeaver / SQLiteStudio / VSCode 插件）直接改库 | 否 |
| 改导购回答逻辑 | 改 `agent.py` | **是** |

> ⚠️ 用 `--force` 灌库会用 `products.py` 覆盖数据库里的商品改动。
> 如果两边都改过，先确认哪份是新的，别把数据库里的改动冲掉。

## 二、添加一个新商品（完整步骤）

以「添加 SKU025 康师傅红烧牛肉面」为例，**只需改 `products.py` 一个文件**：

```python
Product(
    sku_id="SKU025",                    # 必须唯一，建议按顺序递增
    name="康师傅 红烧牛肉面",
    brand="康师傅",
    category="零食",                     # 饮料 / 零食 / 日用，影响分类筛选
    spec="105g 桶装",
    price=5.5,
    member_price=4.9,
    shelf=ShelfLocation(
        aisle="A2",                      # 货架编号
        level=2,                         # 层号，1 为最底层
        desc="A2 零食架第二层，方便面专区",  # 这句话会被导购直接念给顾客
    ),
    nutrition=Nutrition(energy_kj=1900, protein_g=9.0, fat_g=18.0,
                        carb_g=60.0, sodium_mg=1800),
    ingredients="小麦粉、棕榈油、牛肉粉、食用盐、辣椒",
    allergens=["小麦", "大豆"],           # 没有就留空列表 []
    tags=["方便速食", "高钠"],            # 影响搭配推荐，见下文
    promotions=[],                       # 需要就加 Promotion(type="second_half", desc="第二件半价")
    visual=VisualProfile(
        color="#C8102E",                 # 主色，界面上商品块的颜色
        color2="#FFD700",                # 辅色，包装上的色带
        shape="cup",                     # can瓶罐 / bottle / box / bag / tube / pack / cup
        label="牛肉面",                   # 图上显示的短标签，2-3 字
        weight_g=110,                    # 单件重量（克），用于称重校验，务必填准
    ),
),
```

然后执行灌库命令（**不需要重启后端**）：

```bash
cd backend && python -m app.db.seed --force
```

添加后自动获得的能力：导购可以回答它的位置/营养/过敏原、视觉结账可以识别它、称重校验自动计入它的重量。

也可以直接用 SQLite 工具往 `products` 表插一行，同样立即生效。

### 三个容易踩的坑

1. **`weight_g` 要填实际重量**，否则称重校验会误报漏检
2. **相似包装要加进 `SIMILAR_GROUPS`**，例如新口味与旧口味包装接近：
   ```python
   SIMILAR_GROUPS = [..., ["SKU025", "SKU026"]]
   ```
   这样识别时才会在两者间犹豫并追问顾客，而不是直接猜错
3. **`tags` 决定搭配推荐**：`_pairing_reason()` 是按标签匹配的，
   打上「膨化食品」「咖啡」「辣味」等标签，推荐才有依据

## 三、修改导购的回答方式

### 3.1 无 Key 时（本地知识库）

改 `agent.py` 的 `_local_answer()`，按意图分支返回文本：

```python
if intent == "location":
    text = f"「{main.name}」在 {main.shelf.aisle} 货架第 {main.shelf.level} 层。\n..."
    return text, [...]
```

### 3.2 想让新的问法被识别

改 `INTENT_RULES`，加关键词即可：

```python
("pairing", ["搭配", "推荐", "一起", "配什么", "组合", "搭子", "下酒"]),
```

### 3.3 有 Key 时（真实大模型）

改 `SYSTEM_PROMPT` 控制语气与约束，改 `TOOLS` 增加工具。
**注意**：加了工具必须同时在 `run_tool()` 里实现对应分支，否则模型调用会落进默认分支。

## 五、改完不生效？按顺序排查

1. **改了 `products.py`** → 需要跑 `python -m app.db.seed --force` 灌库
   （只改文件不会自动同步到数据库）
2. **直接改了数据库** → 立即生效，不用重启
3. **改了 `agent.py` / 任何 `.py`** → 必须**手动重启后端**
   （`--reload` 在本机 Windows 环境下不触发）
4. **改了 `.vue` / `.ts`** → 前端热更新，刷新浏览器即可
5. **改了 `.env`** → 必须重启后端
6. 页面没反应且没有报错 → 打开浏览器控制台（F12）看 Network 面板，
   确认 `/api/v1/...` 请求是否 200
